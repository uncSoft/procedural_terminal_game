# Bosses in 3D: sprite → Blender → frames → the game's clips

The pipeline that turns a boss's 24-pixel sprite into the animated clips the stage plays when its fight starts
(`src/ptg/data/clips/<boss>/`, played by `encounter.Fight`). The sprite is made solid, rigged and animated in Blender,
rendered from the front, shrunk back to sprite size in the sprite's own colours, and cut into the game's strips. Every
boss has been through it: the Goblin King, King Mouse, Serpentis, the Drowned Abbot and the Thornmother.

It started as a spike (the voxel goblin: `voxelize.py`, `build_goblin.py`, `pixelate.py`, `frames/`), which looked
lumpy once turned and shrunk. The bosses are built smooth instead.

## What you need

- Blender (4.x or later; 5.3 was used), run headless from its command line. On a Mac:
  `B=/Applications/Blender.app/Contents/MacOS/Blender`.
- The repo's Python (`uv`), with numpy for the inflate and reduce steps (`--with numpy`).

## The steps, for one boss

Each boss has its own `inflate_<boss>.py` and `build_<boss>.py`, and a folder of its own (`king/`, `king_mouse/`,
`serpentis/`, `drowned_abbot/`, `thornmother/`). The Thornmother's, as an example:

```bash
# 1. The sprite made solid: scaled up the pixel-art way (EPX), each part inflated like a balloon (Poisson), smoothed,
#    with what a front view can't show filled in. Writes thornmother/thornmother_mesh.json (and its palette).
uv run --no-sync --with numpy python spikes/goblin3d/inflate_thornmother.py

# 2. Built, rigged and animated in Blender: thornmother/thornmother.blend and .glb
$B -b --factory-startup --python spikes/goblin3d/build_thornmother.py -- build

# 3. Its four clips rendered from the front, 256 pixels, toon-shaded in the sprite's colours:
#    thornmother/frames_hd/<Clip>/0/<frame>.png
$B -b spikes/goblin3d/thornmother/thornmother.blend --python spikes/goblin3d/build_thornmother.py -- frames
#    (or a few frames of one clip, to check a pose: -- test Attack 0 5 8)

# 4. Shrunk to the game's sizes in the sprite's palette, with the game's one-pixel outline round them:
#    thornmother/frames_40, _48, _64, _84
uv run --no-sync --with numpy python spikes/goblin3d/reduce.py thornmother 40 48 64 84

# 5. Watched in the terminal, the game's half-block way: one boss, or all of them putting on a show together
uv run python spikes/goblin3d/play.py spikes/goblin3d/thornmother/frames_64 --fps 24 --start entrance --once entrance
uv run --no-sync python spikes/goblin3d/gallery.py

# 6. Into the game: a strip per clip and size, data/clips/thornmother/<clip>.<size>.png
uv run python tools/make_clip.py spikes/goblin3d/thornmother/frames_48/Entrance/0 thornmother entrance --fps 24
```

Do step 6 for each of entrance, idle, attack and windup, at each size; the entrance's landing frame (where the boss
sting plays and the name card starts) is found by itself. `tools/make_clip.py` says what each clip is for. Then add
the boss to the clip test in `tests/test_encounter.py`.

`frames_hd/` isn't kept in git (it's 256-pixel renders, regenerated by step 3 from the `.blend`); everything else is:
the scripts, each model's mesh and palette (`*_mesh.json`, which `reduce.py` reads), the `.blend` and `.glb`, and the
game-size frames, so `gallery.py` and `play.py` work without Blender.

## The brief each boss is made to

- From the front only (direction 0), the same camera for all (`SPAN` 48, 12° above), 24 frames a second.
- Four clips: **Entrance** (from off the frame, a clear landing on its feet, a show-off, ending in the idle's first
  pose), **Idle** (about a second, looping), **Attack** (about 20 frames, from the idle's pose and back to it; note
  the frame the blow lands), **Windup** (about 10 frames: the held threat before a heavy blow; the monster's `tell` in
  `monsters.toml` says what it should show).
- The sprite's own palette only, plus the `#181425` outline.
- Standing about 21, 25, 32 and 42 pixels tall at frames 40, 48, 64 and 84 (the same pixel scale as the King). No
  wider than one and a half times its height, and only the top may leave the frame.
- Touching up a kid's design is fine as long as it stays theirs.

## What we learned

- Check every frame for anything below the idle's feet, or at the frame's sides and bottom: tails, splayed legs, a
  tongue from a lowered head and arms carried down by a bending body have all gone through the floor.
- One-pixel faces boil at 40: grow the dark face pixels by an eighth of a pixel, or draw eyes as decals. Squarish eyes
  (a superellipse) stay blobs at 84 and dots at 40; round ones turn into crosses.
- One-pixel spines vanish under EPX and smoothing: rebuild them as tubes with a coloured tip.
- `reduce.py`'s outline fills any gap under about two pixels: parts a pixel apart in the sprite (coils, an arm by the
  body) must be modelled no wider than drawn, or they merge into a dark block.
- Shrunk to 21 pixels, a strike toward you reads as a crouch: keep blows in the picture's plane, and claws and weapons
  outside the silhouette.
- A stretching bone chain compounds down its children: set `inherit_scale = "NONE"` on the head, the arms and each
  later stretch.
- A boss whose lowest point isn't on row 22 sets `kit.GROUND` (the Abbot's drips, the Thornmother's roots: 23) so it's
  framed like the others. Flaring a hem or root mustn't scale its depth, or it sinks below the floor from 12° above.
- Thin things touching the floor flicker in and out of the bottom row: make them blunt and end them level on screen.
- Even a 1.5° tilt breaks a one-pixel painted band at 40: keep held poses upright.
- From 12° above, a part that sits forward (a face) looks lower than drawn: raise it about half a pixel.
- A body leaning into a strike rolls the face with it: counter-roll the head.
- Later bosses reuse the King's helpers (`build_king`: `P`, `animate`, `build_rig`..., setting `kit.TAG`),
  `build_mouse.blend`, and `inflate_mouse`'s `surface`, `decal`, `cells` and `catmull`.

## Items, and drawing a model live (a spike, on branch spike/terminal-3d)

The Jar o' Light (`build_jar.py`) is a test of an item you can turn over in the game. It's built straight in Blender
(a turned glass jar and lid, eight bugs flying round inside, sparks) and seen from every side, unlike the bosses.
Its glass is part see-through and part glass that lets light through, so EEVEE, Cycles and Solid view all see the bugs
through it. For frames, `build_jar.py frames` renders 32 turns of its loop, leaving the see-through glass out, and
`reduce_jar.py` shrinks them and draws the glass's outline as the sprite does: pale down its lit side, slate elsewhere.
`play.py jar_o_light/frames_64 --spin` turns it in the terminal.

The game can also draw it live, turning however you turn it: `build_jar.py live` writes a lighter copy of the model,
with its animation baked a frame at a time, to `src/ptg/data/models/jar_o_light.json`. `ptg/model3d.py` draws that
into pixels from any angle, in the sprite's own colours and with the glass's outline, in about a millisecond a frame
with only Pillow, and the game shows the pixels as half blocks like any sprite. In the pack, `t` (or "Turn it over")
opens it in a window, `ui/model_view.py`: drag it, arrows, space to spin, + and - to zoom, r to reset.

    uv run python -m ptg.ui.model_view jar_o_light     # just the window, without a game
    uv run python -m ptg.model3d jar_o_light 96        # how long a frame takes, and a few saved to look at

### Every item's model, and a new item's

Every item with a sprite has a model the game draws live, made straight from its sprite by `item_model.py` (no
Blender), in the sprite's own colours. `item_models.toml` lists how each is made, one line an item:

| Way | For | What it does |
|---|---|---|
| `slab` | flat things: blades, keys, cards, sheets | the drawing given depth, every pixel a block (as Minecraft draws what's in your hand); `thick` sets how many pixels (2) |
| `puffed` | soft, round, lumpy things seen from the side: food, clothes, skulls, creatures | a relief, thicker toward the middle in steps of a pixel |
| `turned` | round, upright things: bottles, pots, bombs, torches | turned on a lathe from the sprite's rows, each row as wide and shaded as drawn, so the shine stays on the lit side as it turns; what's drawn on its front is painted on |
| `jar` | a glass jar with something in it | the glass as its outline (pale down its lit side), the lid turned, what's in it floating inside, facing you |
| `ring`, `dice`, `cheese` | where the sprite can't say the shape | shaped by hand in `item_model.py`, in the sprite's colours |
| `blender` | the Jar o' Light | made by its own Blender script (`build_jar.py live`) |

Whichever way, small things drawn apart from it (a sparkle, steam, a speech bubble) stay where they were drawn, beside
it, however it's turned, and twinkle as the sprite's frames do. An item that isn't listed is made as a slab; an item
with no model has no "Turn it over" in the pack.

**For a new item** (or one drawn again):

1. Its sprite is in `src/ptg/data/sprites/item_<key>.png`, as for any item (the Monster & Item Maker puts it there).
2. Pick its way and add a line for it to `item_models.toml`, such as `pickle = "puffed"` or
   `scroll = { way = "slab", thick = 1 }`. Any line can also set `pitch`, how far down it's looked at to begin with.
3. Make it: `uv run python spikes/goblin3d/item_model.py <key>`. It writes `src/ptg/data/models/<key>.json`.
4. Look at it turning: `uv run python -m ptg.ui.model_view <key>` (drag it, the arrows, space), or every model beside
   its sprite: `uv run python spikes/goblin3d/item_model.py --sheet models.png`.
5. If it looks wrong, try another way. If none fits (the sprite is drawn from above, or the thing is a shape no drawing
   gives), shape it by hand: a function in `item_model.py` like `dice` or `cheese`, in the sprite's colours, listed in
   `WAYS` and named in its line.
6. Run `uv run pytest tests/test_model3d.py`: every model must stay in its sprite's colours, and be made from the sprite
   as it's drawn now (each model remembers which; a redrawn sprite fails until its model is made again).
7. Commit its line and its `.json` with the sprite.

To make every model again (after changing how a way works): `uv run python spikes/goblin3d/item_model.py all`.
