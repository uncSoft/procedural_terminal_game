# W13-panel-actions: A8/A3 UI: equip, swap, drop, give and 'use on' from the panels, with every panel sending engine actions directly.

Read RULES.md and DECISIONS.md (same folder as this brief) first. The owner's decisions override the plan's approach wherever they differ.

## Approach (from the fix plan)
- Panels run engine Actions directly, no longer translated to 'the nth choice'.
- InfoScreen asks the engine which actions apply to a thing (scene refs plus off_the_list), so:
  - a lying item always offers Take;
  - a calm character offers primary_actions first.
- Inventory: Weapon and Armor slots above the pack. Each item has Equip/Unequip, Drop, Use, Throw, Give to…, and a 'Use on…' target picker built from RoomView that sends the same Intent v2 the interpreter emits.
- Shop: a stat comparison with your gear, a 'spare' warning, and a Sell tab.
- Journal: an open-quests section.
- Choices keep stable slots: used features stay greyed as '(searched)', and movement gets a fixed block.
- A single 'Give…' row and a single 'Use an item…' row replace the per-item rows.

Files likely involved: src/ptg/ui/panels.py, src/ptg/ui/game_screen.py, src/ptg/ui/widgets.py, src/ptg/rules.py, tests/test_ui.py, tests/test_shops.py

## From the layout spike's review (fixes meant for the real build)

- [build] Phones never reach the phone layout. serve.py renders textual-serve's own app_index.html (PlayersServer passes no templates_path). That page has no <meta name=viewport> and a fixed 16px font, so a phone lays out a desktop-width page (about 980 CSS px) of about 102 columns and the narrow class never triggers. The iOS keyboard covers the bottom half without resizing the terminal. Swipes don't scroll, because xterm.js handles touch only when mouse reporting is off, and Textual always turns it on. When the terminal does resize for the keyboard, the whole layout rebuilds.
  FIX: Ship a ptg app_index.html and pass templates_path. Include: a viewport meta tag with interactive-widget=resizes-content; '#terminal { touch-action: manipulation }'; a font size chosen from innerWidth so phones get at least 40 columns (clamp(11, floor(innerWidth/40/0.6), 16)); terminal height set from visualViewport on resize; a touch-to-wheel shim that turns touchmove into WheelEvents on .xterm-screen; inputmode='none' on xterm's helper textarea until a ⌨ button is tapped; and a pointer:coarse touch flag passed to the game as PTG_TOUCH, so touch mode follows the input type rather than the width. Add a 'typing' class, set while the command line has focus and the height has dropped by 35% or more, that leaves only the HUD, the story and a 1-row command line. Then play scenes 1-4 on a real iPhone and a real Android phone at about 40x34, 52x51 and in landscape.
- [build] The tile verbs are made up rather than taken from the engine. The ids 'talk:', 'give_to:', 'use_on:', 'sell' and 'equip:' don't exist, and some verbs are wrong in context. 'Take' shows on the Flask mid-fight, which action_pick_up refuses. 'Equip' shows on any weapon or armour you aren't wearing, but there is no equip action; gain_item only auto-equips a higher tier. 'Sell…' has no engine support. Item statuses are category labels ('trinket', 'weapon') that don't say whether the Hand Axe on the floor is the same as yours or whether the War Pick beats your sword, and potions and pickles only offer 'Take'. Swoogy's Talk and Give… can't start or play his game. While he is guessing, choices 3-8 are 'Guess 1' to 'Guess 6', so typing 3 guesses 1, and the 11 choices overflow narrow screens.
  FIX: Build the verbs with verbs_for(thing, game.choices()), matching action ids by their target key: take:, use:/throw:/distract:, appease:, the character's npc actions, ask/attack for the room's monster, and shop for the keeper. Route clicks through run_turn(str(index)) with the busy/over guards. Hide Equip, Give and Sell until rules.py has real equip:, give: and sell: actions (that is the equip/swap work). Statuses should compare gear with what's equipped ('▲ better than your Rusty Sword', 'same as yours', '▼ weaker'). Consumables get 'Drink' or 'Eat', and trinkets get a one-line hint plus 'Look'. When Swoogy is guessing, give his tile ⚀-⚅ verbs (guess:1 to guess:6) and have the engine list the guesses first, so choice n is Guess n. Show a run of guess:n actions as one '[1] ... [6]' row.
- [build] Once pictures leave the story, fight and fixture animations have no place to play. Tile has no play() method. Animating the stage instead means re-rendering picture_text every frame: about 25 ms and 105 KB of ANSI at 140x40 px. A 14-step hit-and-lunge sequence would cost about 1.5 MB per served player and block the event loop for 350 ms. A sprite frame costs 0.03 ms and 5 KB. The room's fixture (fountain, coffin, chest, shrine, stairs) isn't in Here, even though scene 1 offers 'Drink from the strange fountain'. Today _fixture_moment and _arrival_sprite mount their animated sprites in the story.
  FIX: Make Tile wrap widgets.AnimatedSprite, which already has play, freeze, resume and become. Note that AnimatedSprite.play takes (frame, pose, flash) while _play_scene uses (pose, frame, flash).
